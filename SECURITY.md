# Анализ безопасности

Дата проверки: 2026-11-01.

## Область и модель угроз

Проверены `index.html`, `game.js`, стили и локальные ресурсы, зависимости npm, Playwright-тесты и workflow GitHub Pages. «Напальчик» — полностью статическое клиентское приложение: серверной части, аккаунтов, платежей, API, cookie и сбора телеметрии нет.

Основные риски для такой архитектуры — внедрение скриптов в DOM, компрометация зависимостей или процесса публикации, сторонние сетевые запросы и повреждение локальных данных. Серверные уязвимости (SQL-инъекции, SSRF, небезопасная загрузка файлов и т. п.) неприменимы.

## Результаты

Критических, высоких и средних уязвимостей в проверенной области не обнаружено.

- **DOM/XSS.** Пользовательский ввод и удалённые данные в HTML не вставляются. Игровые значения выводятся через `textContent`. Единственная вставка `innerHTML`, хотя и содержала только фиксированные строки, заменена на безопасное создание DOM-узлов.
- **Content Security Policy.** Добавлена CSP: разрешены только локальные скрипты и ресурсы, запрещены плагины, не ограниченные источники и отправка форм. Отдельно разрешены только используемые Google Fonts. Добавлен `Referrer-Policy: no-referrer` через meta-элемент.
- **Локальное хранилище.** Сохраняются только рекорд и настройка звука; конфиденциальные данные отсутствуют. Рекорд теперь принимается только как неотрицательное безопасное целое число. Повреждённые значения, `Infinity` и посторонние строки отбрасываются. Если хранилище недоступно (например, из-за ограничений приватного режима), ошибки перехватываются.
- **Сеть.** Игровой код не выполняет `fetch`, XHR или отправку данных. Внешние запросы относятся только к загрузке шрифтов Google; изображения, скрипты и звуки приложения не загружаются со сторонних доменов.
- **Зависимости.** Production-зависимостей нет; Vite и Playwright используются только для разработки и сборки. Версии зафиксированы через `package-lock.json`, установка в CI выполняется через `npm ci`. `npm audit` на дату проверки сообщает об **0 уязвимостей**.
- **GitHub Actions.** Действия закреплены полными SHA коммитов вместо изменяемых тегов. Права `pages: write` и `id-token: write` выделены только заданию публикации; сборка имеет доступ `contents: read`.
- **Регрессионная проверка.** Добавлен тест, подтверждающий блокировку встроенных скриптов политикой CSP и отбрасывание некорректного сохранённого рекорда.

## Остаточные риски и рекомендации

1. **Низкий: сторонние шрифты.** При загрузке Google Fonts оператор CDN получает стандартные сетевые метаданные, включая IP-адрес. Для полного исключения сторонних запросов шрифты можно разместить локально.
2. **Низкий: защита от встраивания.** Meta-CSP не поддерживает `frame-ancestors`. Если потребуется защита от clickjacking, заголовок CSP с `frame-ancestors 'none'` следует настроить на уровне хостинга; GitHub Pages не позволяет задавать произвольные HTTP-заголовки.
3. **Не является границей безопасности: рекорд.** Посетитель может изменить собственный `localStorage` и локальный рекорд. Это влияет только на его браузер и не даёт доступа к другим пользователям или серверным данным.
4. Регулярно выполнять `npm ci`, `npm audit`, `npm test` и `npm run build`, обновлять зависимости и перепроверять SHA действий GitHub при их обновлении.

Эта проверка является статическим аудитом текущей версии и не заменяет регулярный контроль зависимостей и инфраструктуры.
